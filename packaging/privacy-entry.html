Parkett (macOS, Windows, Linux) — Privacy

Parkett is an open-source desktop application that shows Apache Parquet files: the rows in a grid, and what a file says about itself in a panel beside it. It reads the file you open and writes nothing but what you ask it to. It makes no network connection of any kind. This section is the canonical statement of what Parkett does and does not do with your data. The application is open source so that every claim here is independently verifiable. The repository is at github.com/excelano/parkett.

The short version

Parkett talks to nothing. There is no server behind it, no account to create, no analytics, no telemetry, no crash reporting, and no third-party service. It reads the Parquet file you open, never changes it, and writes a CSV only when you export one, to the place you choose. On the stores its App Privacy declaration is “Data Not Collected,” because the developer collects nothing and has nowhere to put it.

What stays on your device

Nothing between runs. Parkett keeps no settings file, no list of recent files and no remembered folder. Close the window and nothing of the session remains on disk.

What it writes is what you asked for, where you said. File, Export as CSV writes a new file at the location you choose in the save dialog, and refuses the Parquet file itself as a destination. The CSV is written whole before it takes the place of anything already at that location, so an export that fails or is cancelled leaves what was there as it was. Copy puts the cells you selected on the clipboard, where any application you paste into can read them.

What leaves your device

Nothing. Parkett makes no network request. It has no update check, no license check, no analytics service, no crash reporter, and no remote logging, and its dependency tree contains no HTTP client.

Except what you hand to another application. When an export finishes, its Open button passes the CSV to whatever your computer has registered for CSV files. From that moment the file is in that application's hands and subject to that application's behaviour, not to this one's.

What Parkett does not collect

Parkett does not collect the contents of your files, their names, what you opened, when, how often, which cells you selected, which buttons you pressed, screen views, crash reports, performance metrics, diagnostic logs, device identifiers, advertising identifiers, installation identifiers, or anything else. It has no way to, because it makes no network connection. This section and the open-source repository are the substance behind the “Data Not Collected” label.

One thing outside the application's control

Both stores collect their own figures about installs and, on Apple's platforms, aggregate anonymous crash logs from devices where Share With App Developers is turned on. Parkett neither collects that data nor contains any code that touches it, but the store may still show the developer account aggregate, anonymised numbers regardless of what the application does. On macOS the control is at System Settings > Privacy & Security > Analytics & Improvements > Share With Mac Developers; on Windows, under Settings > Privacy & security > Diagnostics & feedback. Either applies to every application, not only this one. A copy installed from the Excelano apt repository, from crates.io or built from source involves no store at all.

How to verify the claims yourself

The full source is at github.com/excelano/parkett. To check the claims here independently:

  1. Search the project for anything that opens a network connection. There is nothing: no HTTP client, no TCP or UDP socket, and no URL is contacted. cargo tree on the repository lists what is compiled in. On Linux, lsof -i against the running application lists nothing at all. What it does open are local sockets, to the display server and to the session message bus, which is how the file dialog is shown and how Parkett asks whether the desktop is set to light or dark. Both stay on this machine, and what goes over them is a dialog and a display setting, never your files.
  2. Search for analytics and crash-reporter names: Firebase, Sentry, Crashlytics, Mixpanel, Amplitude, Segment, GoogleAnalytics. None appears.
  3. Search for what is written to disk. One thing: a CSV you export, at the destination you chose. There is no configuration file and no cache.
  4. Confirm there is no server component in the repository. There is nothing to self-host, because Parkett has no backend by design.
